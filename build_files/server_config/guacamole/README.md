# Guacamole Image Management

This guide describes how to build and deploy Guacamole server images across three distinct states. It also references existing configuration files without reproducing them fully.

---

## TL;DR
1. **Set Required Secrets**: Ensure all environment variables and secrets (including your DNS admin key) are in place for DNS validation in GCP.
2. **Create a Base Image**: Either copy `image-guac-base` from an existing project (e.g., `agoge-test-427119`) or build it from scratch.
3. **Create a Project-Specific Image**: Use the [setup.py](/setup.py) deploy script. Choose “Server Images and Build Specs,” then select “Refresh/Create guacamole image and certificate.” Opt to deploy wildcard certificates if prompted.
4. **Use the New Image**: Once checked in, labs can use the new project-specific Guacamole image and certificate.

---

## Overview: Three States

1. **`image-guac-base`: Base Guacamole Ubuntu Server**
   - Minimal OS with Docker and basic tooling.
   - Includes configuration files but **no** project-specific environment variables.
   - No containers are running.

2. **`image-guac-<project>`: Project-Specific Guacamole with Wildcard Certificate**
   - Inherits from `image-guac-base`.
   - Uses a startup script (in [GuacamoleImageManager](/build_files/cloud_deployment/operations/guacamole_image_management/guacamole_image_manager.py)) to configure project variables and request a wildcard cert.
   - Results in a fully configured, project-specific Guacamole image.

3. **Lab Deployment**
   - Inherits from `image-guac-<project>`.
   - When a lab spins up a server, [GuacamoleConfiguration](/cloud_fn_utilities/server_specific/guacamole/guacamole_configuration.py) sets the hostname, domain, and creates dynamic user accounts.

## 1. Creating the Base Guacamole Ubuntu Server

### 1.1 Install Ubuntu Prerequisites
1. **Update Packages**:
   ```bash
   sudo apt-get update -y
   sudo apt-get upgrade -y
   ```
2. **Install Base Dependencies**:
   ```bash
   sudo apt-get install -y \
       apt-transport-https \
       ca-certificates \
       curl \
       software-properties-common \
       net-tools \
       certbot \
       python3-certbot-dns-google
   ```

### 1.2 Install Docker and Initialize Swarm
1. **Install Docker**:
   ```bash
   sudo apt install -y docker.io
   sudo systemctl enable docker
   sudo systemctl start docker
   ```
2. **Initialize Docker Swarm**:
   ```bash
   sudo docker swarm init
   ```

### 1.3 Set Up Directories and Configuration Files
Create a directory and populate it:

```bash
/opt/guacamole
├── docker-compose.yml
├── initdb.sql
├── nginx
│   └── conf.d
│       └── guacamole.conf
└── scripts
    ├── update-admin-password.sql.template
    └── update-password.sh
```

Steps:
1. **Create directory**:
   ```bash
   sudo mkdir -p /opt/guacamole
   cd /opt/guacamole
   ```
2. **Copy Configuration**:
   - [**`docker-compose.yml`**](./configs/docker-compose.yml)
   - **`initdb.sql`** (generated by Guacamole’s init script):
     ```bash
     sudo sh -c "docker run --rm guacamole/guacamole /opt/guacamole/bin/initdb.sh --mysql > initdb.sql"
     ```
   - **`scripts/update-admin-password.sql.template`**
   - **`nginx/conf.d/guacamole.conf`**

After adding all necessary files, **capture** this image as `image-guac-base`.

---

## 2. Creating the Project-Specific Image

1. **Boot from `image-guac-base`**.
2. **Add Environment Variables and Certificates**:
   - Populate `/opt/guacamole/.env` with domain info, DB credentials, hashed admin password, and your Google DNS JSON.
   - Run your project-specific startup script ([`project-guac-gcp-startup-script.sh`](../../cloud_deployment/operations/guacamole_image_management/guacamole_image_manager.py)) to enable and configure `guacamole.service`.
3. **Capture the Image**:
   - Once everything is configured, save this state as `image-guac-<PROJECT>`.

---

## 3. Lab Deployment (Dynamic Host)

1. **Clone from `image-guac-<project>`**.
2. **Override Hostname**:
   - Edit `/opt/guacamole/.env` to set `GUAC_HOST`.
3. **Startup Script**:
   - Dynamically generated by [GuacSQL](/cloud_fn_utilities/server_specific/guacamole/guacamole_configuration.py) to adjust Nginx, add users, etc.

---

## Summary of the 3 Versions
1. **Base Image** (`image-guac-base`): Minimal OS + Docker + default configs.
2. **Project Image** (`image-guac-<PROJECT>`): Adds environment variables, wildcard cert, and systemd service.
3. **Lab Deployment**: Running instance derived from the project image, with updated environment variables.

**All subsequent images** after the base include a systemd daemon to ensure containers start on reboot. MySQL data and SSL certificates are kept in Docker volumes.

```bash
sudo certbot renew --dns-google \
  --dns-google-credentials /secrets/dns-google.json \
  --dns-google-propagation-seconds 60
```

## Docker Swarm Configuration
Defined by [docker-compose.yaml](/build_files/server_config/guacamole/configs/docker-compose.yml), which deploys:
1. **MySQL (db)**:
   - MySQL 8.0
   - Stores persistent data on `db_data` volume
2. **Guacamole Daemon (guacd)**:
   - Manages remote desktop protocols
   - Shares `guac_recordings` volume
3. **Guacamole Web App (guacamole)**:
   - Web interface for Guacamole
   - Uses MySQL and `guac_recordings`
4. **Nginx (nginx)**:
   - Reverse proxy on ports 80/443
   - Loads certs from `/etc/letsencrypt`

All services run with minimal replicas, overlay network (`guacnet`), and named volumes (`db_data`, `guac_recordings`) for persistence.

## NGINX Configuration
[guacamole.conf](/build_files/server_config/guacamole/configs/guacamole.conf) includes:
1. **HTTP (80)**: Redirects all traffic to HTTPS.
2. **HTTPS (443)**: Loads wildcard cert, proxies requests to `guacamole:8080`, and passes WebSocket headers.

## Project Image Startup Script
[GuacamoleImageManager](/build_files/cloud_deployment/operations/guacamole_image_management/guacamole_image_manager.py) performs:
1. **Environment Setup**
2. **Wildcard SSL Certificate Acquisition** via Certbot
3. **Docker Swarm Deployment** using `docker-compose.yml`
4. **MySQL Password Update** after readiness checks
5. **Secrets Cleanup** to remove sensitive files

## Lab Startup Script
[guacamole_configuration.py](/cloud_functions/cloud_fn_utilities/server_specific/guacamole/guacamole_configuration.py) handles:
1. **Single-Run Check** to avoid repeated initialization
2. **DNS/Host Updates** for Nginx
3. **Wait for MySQL** before applying user/SSH settings
4. **SQL Execution** for new users and connections
5. **Completion Marker** (`/etc/guac_init_done`)
