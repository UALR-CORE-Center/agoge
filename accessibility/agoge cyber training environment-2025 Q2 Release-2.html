Evaluation Methods Used Anchor link

The accessibility assessment of the Agoge CTE (Student Mode) software involved a combination of manual inspection, automated tools, and assistive technology testing.

Manual Code Inspection - Evaluators reviewed the provided HTML, CSS, JavaScript, and React component source files to identify accessibility support and gaps according to WCAG 2.1 guidelines and Section 508 Functional Performance Criteria.

Automated Testing: Lighthouse was used to perform automated analysis on sample pages and interactive components, verifying compliance with WCAG 2.1 Level A and AA success criteria.

Keyboard Navigation Testing: Manual keyboard navigation tests (Tab, Shift+Tab, Enter, and Spacebar) were conducted to verify operability, focus visibility, and absence of keyboard traps throughout user workflows.

Color Contrast Analysis: Contrast levels were evaluated using WCAG-approved color contrast analyzers (e.g., WebAIM Contrast Checker) for text and interactive elements.

Identified accessibility issues have been documented, and specific enhancements are planned and detailed in this report, targeted for completion in the 2025 Q4 software release.

Terms Anchor link

The terms used in the Conformance Level information are defined as follows:
  • Supports: The functionality of the product has at least one method that meets the criterion without known defects or meets with equivalent facilitation.
  • Partially Supports: Some functionality of the product does not meet the criterion.
  • Does Not Support: The majority of product functionality does not meet the criterion.
  • Not Applicable: The criterion is not relevant to the product.
  • Not Evaluated: The product has not been evaluated against the criterion. This can be used only in WCAG 2.x Level AAA.
