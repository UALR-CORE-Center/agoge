# Agoge Cyber Training Environment

## Release v2026.01

**Release Focus:** Accessibility, reliability, and simplified cloud operations

## What’s New in v2026.01

The v2026.01 release delivers meaningful improvements in four key areas:

1. Improved accessibility compliance for student workflows  
2. Faster, more reliable lab provisioning  
3. Simplified and more stable remote lab access  
4. Unified proxy-based access across courses and institutions  

These updates improve usability for all learners while reducing setup time and operational complexity for instructors and administrators.

## 1. Improved Accessibility for All Learners

Agoge v2026.01 significantly enhances accessibility across the student experience, meeting WCAG 2.1 Level AA and Section 508 requirements.

### What this means for students

* **Screen-reader friendly navigation**  
  Clear headings, landmarks, and announcements make labs, workouts, and assessments easier to navigate using assistive technologies.

* **Keyboard-first usability**  
  All interactive elements, including tables, dialogs, and controls, can be accessed and operated entirely via keyboard, with clear visual focus indicators.

* **Clearer status and feedback**  
  Lab status changes, timers, and system messages are now announced clearly and consistently, reducing confusion during lab work.

* **Better form guidance**  
  Input errors are easier to understand and fix, with specific, actionable feedback rather than generic error messages.

* **Improved color and contrast**  
  Status indicators and interface elements no longer rely on color alone, helping users with low vision or color-blindness.

### Who benefits

These enhancements support:

* Students using screen readers  
* Students with low vision or color-blindness  
* Students who rely on keyboard navigation  
* Students who benefit from clearer structure and feedback  

Accessibility improvements are applied consistently across **Student Mode**, including labs, assessments, and workouts.

## 2. Faster and More Reliable Lab Provisioning

Agoge now uses a central, managed image library for lab environments rather than maintaining duplicate images in every customer project.

### What this means for instructors and administrators

* **Faster lab startup**  
  New labs launch more quickly because images are no longer copied or rebuilt per project.

* **Greater consistency**  
  All students run labs from the same validated images, reducing unexpected differences between environments.

* **Smoother upgrades**  
  Platform updates can be rolled out without disrupting existing labs or requiring manual image management.

* **No migration required**  
  Existing users continue to work as before, while new deployments automatically benefit from the shared image model.

This change improves reliability while keeping customer environments clean and easy to manage.

## 3. Simplified Remote Access with Centralized Guacamole
Remote lab access through the browser (Guacamole) is now fully centralized and managed as a shared platform service.

### What this means for users

* **No per-project setup required**  
  Guacamole no longer needs to be configured, copied, or maintained inside individual lab projects.

* **More reliable connections**  
  Certificates and DNS are managed centrally, eliminating common causes of connection failures or expired access.

* **Cleaner lab projects**  
  Removing a lab no longer leaves behind unused images or certificates.

* **Consistent student experience**  
  Browser-based access behaves the same across all labs and courses.

For instructors, Guacamole now “just works” as part of the platform—no special handling required.

---

## 4. Unified Proxy-Based Access for Multi-Course Deployments

Agoge now routes all student and API traffic through a **single, shared proxy entrypoint**, providing a consistent and scalable access model across institutions, schools, and courses.

### What this means for instructors

* **One stable URL structure across all courses**  
  Multiple schools or courses can be accessed through a single domain using clear URL paths (e.g., `/school-one/`, `/course-two/`).

* **Improved reliability and isolation**  
  Each course environment is cleanly routed and isolated, while still benefiting from shared infrastructure.

* **Simpler onboarding of new courses**  
  New schools or projects can be added without provisioning new public endpoints or certificates.

* **Predictable behavior for students**  
  Students always enter labs through the same trusted domain, reducing confusion and access issues.

* **Cleaner failure handling**  
  Invalid or outdated links fail gracefully, preventing accidental exposure of unfinished or removed environments.

This proxy-based architecture reduces operational overhead while making Agoge easier to scale across departments, districts, and statewide programs.
